## 补充：file:// 打开导致“点击无反应”的排查（2026-09-15）

用户反馈“点击上传 GLB 无反应”。复现结果：用 file:// 直接双击 index.html 时，浏览器拦截 ES 模块脚本，
bootstrap.js 未执行，app.js 从未加载，所有事件处理器未绑定（`upload.onclick` 为 null），
且报错代码本身也在模块内，因此页面框架正常但无任何提示。

| 打开方式 | 画布 | 上传按钮 | 错误提示 |
| --- | --- | --- | --- |
| http://127.0.0.1:4178（npm start / 启动点阵飞行.command） | 已创建 | 可点击，解析链路正常 | 正常 |
| file:///…/index.html | 未创建 | 无任何反应 | 无 |

修复与补充验证：

- index.html 增加内联经典脚本：file:// 时立即显示指引横幅（含复制地址按钮），并加 3 秒兜底提示；
- 新增 `启动点阵飞行.command`（双击启动服务并打开浏览器），冷启动分支与“服务已运行”分支均已验证；
- 修正 app.js：未上传模型时切到“模型编队”会让点阵目标为空，导致之后拖动进度条静默失效；现回退球形编队并提示；
- 浏览器实测，http 模式下：无横幅、画布正常、上传 samples/torus-knot.glb 生成 1,000 光点、
  播放/暂停/重新编队/编队切换/进度/时长/参考模型开关全部正常。

注：agent-browser 通过 CDP 注入文件测试上传会报 NotReadableError（自动化工具副作用，非应用缺陷），
页面内构造 File 对象的方式可正常复现真实上传链路。
